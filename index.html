传递函数

在经典控制理论中，我们习惯用高阶微分方程或传递函数（如单输入单输出的 $G(s)$）来描述系统。但当系统变得极其复杂（多输入多输出、变量之间严重耦合）时，高阶微分方程会变得无比臃肿，难以用计算机进行矩阵运算。

现代控制理论引入状态空间的核心目的，是通过变量代换，将任意复杂的 $n$ 阶微分方程，统一降阶转化为一阶微分方程组的矩阵形式。

理论推导的核心步骤：

  1. 选取状态变量：挑选出一组能够完全表征系统动态特征的最小变量集合（对于四旋翼，通常选位置、速度、角度、角速度共 12 个变量）。

  2. 列写非线性微分方程：根据牛顿-欧拉定律，写出包含各种物理耦合项的非线性方程。

  3. 平衡点线性化：在特定的工作点（如平稳悬停状态，$\phi \approx 0, \theta \approx 0$）附近，利用泰勒展开略去高阶小量，将非线性方程化为线性差分/微分方程。

  4. 矩阵打包：将线性化后的方程组用矩阵乘积的形式统一表达，即得到了标准的线性连续系统状态空间表达式：

    $$\begin{cases} \dot{X} = AX + BU \\ Y = CX + DU \end{cases}$$

1.确定状态向量X(12维)：$$X = [\dot{x}, \dot{y}, \dot{z}, \dot{\phi}, \dot{\phi}, \dot{\psi}, x, y, z, \phi, \theta, \psi]^T$$（包含了三个方向的速度、三个方向的姿态角速度、三个方向的位置、三个方向的姿态角）

2.确定输入向量U(4维)：$$U = [U_1, U_2, U_3, U_4]^T$$（即总升力 $U_1$ 和三个轴的控制力矩 $U_2, U_3, U_4$）

3.确定输出向量Y(4维)：$$Y = [z, \phi, \theta, \psi]^T$$ （即悬停状态下的飞行高度和三个姿态角）

根据上面的动力学微分方程，结合小角度近似展开，分别得到简化后的高度、滚转、俯仰和偏航公式

原本非线性方程为 $m\ddot{z} = \cos\phi\cos\theta U_1 - K_{fz}\dot{z} - mg$。在悬停平衡点附近，总升力 $U_1 \approx mg$ 且 $\cos\phi\cos\theta \approx 1$。即$$\ddot{z} = \frac{1} {m}U_1 - \frac{K_{fz} } {m}\dot{z} - g$$

忽略高阶项 $(I_y - I_z)qr$，得到：$$I_x\ddot{\phi} = U_2 - K_{ {\tau}X}\dot{\phi} \implies \ddot{\phi} = -\frac{K_{ {\tau}X} } {I_x}\dot{\phi} + \frac{1} {I_x}U_2$$

忽略高阶项 $(I_z-I_x)pr$，得到：$$I_y\ddot{\theta} = U_3 - K_{ { {\tau}Y}}\dot{\theta} \implies \ddot{\theta} = -\frac{K_{ { {\tau}Y} } } {I_y}\dot{\theta} + \frac{1} {I_y}U_3$$

忽略高阶项 $(I_x - I_y)pq$，得到：$$I_z\ddot{\psi} = U_4 - K_{ { {\tau}Z}}\dot{\psi} \implies \ddot{\psi} = -\frac{K_{ { {\tau}Z} } } {I_z}\dot{\psi} + \frac{1} {I_z}U_4$$

在现代控制理论中，状态空间表达式（$A, B, C, D$）和传递函数矩阵 $G(s)$ 并不是孤立的，它们可以通过经典的公式严密转换：

$$G(s) = C(sI - A)^{-1}B + D$$

由于在小角度线性化后，四通道（$z, \phi, \theta, \psi$）已经实现解耦，我们可以直接对其时域线性化微分方程逐个施加零初始条件的拉普拉斯变换。

拉普拉斯变换是控制工程和数学中最伟大的“魔法”之一。它的核心价值在于把微积分运算转换成了代数运算。拉普拉斯变换（Laplace Transform）是应用数学中常用的一种积分变换，符号记为$\mathcal{L}{f(t)}$。它能将时间域（t 域）的实变量函数，转换为复频率域（s 域）的复变量函数。

它的数学定义为：$F(s) = \int_{0}^{\infty} f(t) e^{-st} dt$$

$s$ 是一个复数，通常写作 $s = \sigma + j\omega$（$\sigma$ 代表衰减/发散率，$\omega$ 代表旋转频率）。 $e^{-(\sigma + j\omega)t}$代表了一组随时间衰减或增长的正弦/指数波， 引入了衰减因子 $e^{-\sigma t}$，使得原本在傅里叶变换下不收敛的信号也能被积分和分析。

拉普拉斯变换的公式是$\mathcal{L}{f(t)} = \int_{0}^{\infty} f(t) e^{-st} dt$

对一个函数求导一次 $\dot{f}(t)$，它的拉普拉斯变换是$\mathcal{L}{\dot{f}(t)} = \int_{0}^{\infty} \dot{f}(t) e^{-st} dt$

代入分部积分公式$\int_{0}^{\infty} \dot{f}(t) e^{-st} dt = \left[ f(t) e^{-st} \right]_0^\infty - \int_{0}^{\infty} f(t) \left( -s e^{-st} \right) dt$$

得到$\mathcal{L}{\dot{f}(t)} = s F(s) - f(0)$

在研究无人机动态响应（比如分析阶跃响应、传递函数）时，我们通常假设系统是从静止状态（零初始条件）开始启动的。也就是说，初始位置 $z(0) = 0$，初始速度 $\dot{z}(0) = 0$。

既然初始条件全为 0：

  • 一阶导数 $\dot{z}(t)$ 的拉普拉斯变换就是：$s Z(s) - z(0) = s Z(s)$
  • 二阶导数 $\ddot{z}(t)$ 连续用两次这个性质，就是：$s^2 Z(s) - s\dot{z}(0) - z(0) = s^2 Z(s)$

求解传递函数

对于高度传递函数$G_z(s)$

$$m\ddot{z}(t) + K_{fz}\dot{z}(t) = \cos\phi\cos\theta \cdot U_1(t)$$

初始条件为0，$\ddot{z}(t) \rightarrow s^2 Z(s)$，$\dot{z}(t) \rightarrow s Z(s)$，公式两边进行拉普拉斯变换

$$m s^2 Z(s) + K_{fz} s Z(s) = \cos\phi\cos\theta \cdot U_1(s)$$

整理可得传递函数 $G_z(s) = \frac{Z(s) } {U_1(s)}$：

$$G_z(s) = \frac{\cos\phi\cos\theta} {m s^2 + K_{fz} s} = \frac{\cos\phi\cos\theta} {m s \left(s + \frac{K_{fz} } {m}\right)}$$

对于滚转角传递函数$G_{\phi}(s)$

$$I_x \ddot{\phi}(t) + K_{ { {\tau}X} }\dot{\phi}(t) = U_2(t)$$

公式两边进行拉普拉斯变换

$$I_x s^2 \Phi(s) + K_{ { {\tau}X} } s \Phi(s) = U_2(s)$$ $$I_x s \left(s + \frac{K_{{\tau}X}}{I_x}\right) \Phi(s) = U_2(s)$$

整理可得传递函数 $G_{\phi}(s) = \frac{\Phi(s) } {U_2(s)}$：

$$G_{\phi}(s) = \frac{1} {I_x s \left(s + \frac{K_{ {\tau}X} } {I_x}\right)}$$

对于俯仰角传递函数$G_{\theta} (s)$

$$I_y \ddot{\theta}(t) + K_{ {\tau}Y}\dot{\theta} (t) = U_3(t)$$

公式两边进行拉普拉斯变换

$$I_y s^2 \Theta(s) + K_{ { {\tau}Y} } s \Theta(s) = U_3(s)$$ $$I_y s \left(s + \frac{K_{ {\tau}Y} } {I_y}\right) \Theta(s) = U_3(s)$$

整理可得传递函数$$G_{\theta}(s) = \frac{\Theta(s) } {U_3(s) } $$

$$G_{\theta}(s) = \frac{1} {I_y s \left(s + \frac{K_{ {\tau}Y} } {I_y}\right) } $$

对于偏航角传递函数$G_{\psi} (s)$

$$I_z \ddot{\psi} (t) + K_{ {\tau}Z}\dot{\Psi}(t) = U_4(t)$$

公式两边进行拉普拉斯变换

$$I_z s^2 \Psi(s) + K_{ { {\tau}Z} } s \Psi(s) = U_4(s)$$ $$I_z s \left(s + \frac{K_{ {\tau}Z} } {I_y}\right) \Psi(s) = U_4(s)$$

整理可得传递函数$$G_{\psi} (s) = \frac{\Psi(s) } {U_4(s) } $$

$$G_{\psi}(s) = \frac{1} {I_z s \left(s + \frac{K_{ {\tau}Z} } {I_z}\right) } $$

又可以写作

$$G_z(s) = \frac{\cos\phi\cos\theta} {m s^2 + K_{fz} s} = \frac{\cos\phi\cos\theta} {m s \left(s + K_{fz}\right) }$$ $$G_{\phi}(s) = \frac{1} {I_x s \left(s + K_{ {\tau}X}\right) }$$ $$G_{\theta}(s) = \frac{1} {I_y s \left(s + K_{ {\tau}Y}\right) } $$ $$G_{\psi}(s) = \frac{1} {I_z s \left(s + K_{ {\tau} Z}\right)} $$

这四个传递函数形式完全一致，均为 $\frac{1}{J s (s + a)}$ 型的典型积分加一阶惯性环节。

以高度通道为例：输入是总升力 $U_1$，输出是高度 $z$。升力通过牛顿第二定律产生加速度，加速度积两次变成高度（双重积分的变体），同时受到垂直空气阻尼 $K_{fz}$ 的制约（一阶惯性）。

以姿态通道为例：输入是力矩 $U_2/U_3/U_4$，输出是角度 $\phi/\theta/\psi$。力矩产生角加速度，角加速度积两次变成角度，同时受到旋转空气阻尼（如 $K_{ {\tau}X }$）的制约

PID控制原理

P（Proportional，比例控制）——“看眼前的距离踩油门/刹车”

  • 原理：你离白线还有多远，就按比例输出多大的动力。离得远，油门踩得大；离得近，油门放轻。

  • 现象：如果你只用 P 控制，你会发现快到白线时车速变慢，但由于惯性，你很容易冲过头（超调）；冲过头后你会倒车，结果又倒过头。车会在白线附近来回晃荡，甚至可能一直震荡停不下来。

    作用：决定反应的快慢与力度。

I（Integral，积分控制）——“累积历史误差，消除顽固偏差”

  • 原理：它会把过去的误差“攒起来”。如果车因为上坡或者风阻，用 P 控制死活差了 5 厘米到不了白线，I 就会随着时间推移，发现“怎么老是差一点点？”，于是不断悄悄加大力度，直到把这最后一点残留误差彻底消灭（消除静差）。
  • 现象：它像一个有“记性”的助手，专门对付那些持续存在的微小偏差。但如果积分太强，系统容易反应迟钝或产生大超调。
  • 作用：消除稳态误差，保证绝对精准。

D（Derivative，微分控制）——“看变化的速度，提前预判刹车”

  • 原理：它不看你现在离白线有多远，而是看你靠近的速度有多快。如果发现你冲向白线的速度极快，它就会提前用力踩刹车，防止你冲过头。
  • 现象：它就像一个“预言家”或“阻尼器”，专门给系统踩刹车、增添阻尼，把由于 P 太猛或惯性带来的震荡和超调死死压制住。
  • 作用：抑制震荡，提供阻尼和稳定性。

从严格的控制工程理论来看，PID 控制器是一个结合了比例、积分、微分三种基本运算的线性控制器。

时域连续公式：

$$u(t) = K_p e(t) + K_i \int_{0}^{t} e(\tau) d\tau + K_d \frac{de(t) } {dt}$$

其中：

  • $e(t)$ 是给定目标值与实际输出值之间的误差（$e = 设定值 - 实际值$）。
  • $u(t)$ 是控制器的输出（比如发给电机的总升力或力矩指令）。
  • $K_p$、$K_i$、$K_d$ 分别为比例、积分、微分增益。

复频域（$s$ 域）传递函数： 对上式取拉普拉斯变换，可得到 PID 控制器的传递函数：

$$G_c(s) = K_p + \frac{K_i} {s} + K_d s = \frac{K_d s^2 + K_p s + K_i} {s}$$

参数 上升时间 (Response Speed) 超调量 (Overshoot) 调节时间 (Settling Time) 稳态误差 (Steady-State Error) 系统稳定性 (Stability)
$K_p$ 明显减小（变快） 显著增大（变冲） 小幅影响 减小（但不归零） 过大会导致不稳定
$K_i$ 小幅减小 明显增大（变迟钝/震荡） 增大（变慢） 消除 (归零) 过大会导致不稳定
$K_d$ 极小影响 显著减小（变平稳） 减小（快收敛） 无直接影响 适度增加可增强稳定性

在实际工程（或者像论文中那样在 Simulink 里调参）时，这三个参数极少孤立使用，通常遵循以下经典的组合逻辑：

  1. 先调 $K_p$：把 $K_i$ 和 $K_d$ 归零，先单调 $K_p$，让系统反应变快，直到出现轻微的超调和震荡。
  2. 再调 $K_d$：引入 $K_d$ 把刚才 $K_p$ 带来的震荡和超调狠狠压下去，让曲线变得平滑、快速收敛。
  3. 最后调 $K_i$：如果发现系统最后总是差一小截到不了目标（有静差），再缓缓加入一点点 $K_i$，彻底消除静差，同时注意防止引发新的低频晃动。

仿真

用MATLAB进行仿真实验，参数设置来源于文献[1]

a. 高度 (Height) —— 响应迟缓，调节时间长

  • 超调量：峰值约为 $1.4\text{ m}$（目标阶跃指令为 $1.0\text{ m}$），超调量约为 $40%$，偏大。
  • 动态性能：响应速度较慢，在前 $1.5\text{ 秒}$ 达到峰值后，经历了一个较大范围的下凹（谷值约 $0.88\text{ m}$ 发生在 $3\text{ 秒}$ 左右），直到接近 $4.5\sim 5\text{ 秒}$ 时才勉强稳定在 $1.0\text{ m}$ 附近。
  • 评价：高度通道的阻尼不足、动态耦合较大，调节时间过长，震荡收敛慢。

b. 滚转角 (Roll) —— 响应较快，过渡平稳

  • 超调量：峰值约为 $1.46\text{ rad}$（目标为 $1.0\text{ rad}$），超调量约 $46%$。
  • 动态性能：在 $0.3\text{ 秒}$ 左右快速到达第一个峰值，经过 $2$ 到 $3$ 个周期的衰减震荡后，大约在 $1.5\sim 2.0\text{ 秒}$ 迅速趋于平稳，最终无稳态误差。
  • 评价：响应敏捷，虽然初期超调略高，但整体收敛速度快，控制效果尚可。

c. 仰俯角 (Pitch) —— 动态品质相对较好

  • 超调量：峰值约 $1.5\text{ rad}$（超调量约 $50%$）。
  • 动态性能：响应速度极快（约 $0.25\text{ 秒}$ 达峰），震荡衰减速度比高度和偏航更快，在大约 $1.5\text{ 秒}$ 内基本完成过渡并稳定在 $1.0\text{ rad}$。
  • 评价：内环姿态角的响应速度快，阻尼比滚转和偏航略好，控制收敛干净。

d. 偏航角 (Yaw) —— 动态响应偏慢，调节周期长

  • 超调量：峰值约 $1.5\text{ rad}$（超调量约 $50%$）。
  • 动态性能：上升较慢（约 $0.6\text{ 秒}$ 达峰），且之后的震荡衰减周期较长，历经近 $3.5\sim 4\text{ 秒}$ 才最终稳定。
  • 评价：偏航通道的惯性较大或控制增益匹配不够理想，导致调节时间偏长。

一、小型四旋翼无人机飞行原理

小型四旋翼无人机在平面结构上其呈十字对称均匀分布，其四只旋翼（旋翼１、２、３、４）分别位于十字架结构的前后左右四个端点上，分为前后、左右两组，且飞行时两组旋翼的旋转方向正好相反：一组逆时针转动（１，３），另一组顺时针转动（２，４）．四旋翼飞行器的结构简图如图所示。

由于小型四旋翼无人机特殊的结构，使其仅通过调整旋翼的转速，使无人机的４个顶点受力不同，从而改变飞行姿态．其各种姿态控制如下：悬停状态时，四只旋翼转速相同，且其升力之和等于无人机自身重力；垂直上升或下降时、保持四只旋翼转速相同且同时等量增加或等量下降；仰俯或滚转运动时，保持一组旋翼转速不变，另一组旋翼中一只旋翼转速增加、另一只旋翼等量下降（仰俯时２、４保持不变，１
增加，３降低；１、３保持不变，４增加，２降低）；偏航运动时一组旋翼转速增加，同时另一组转速下降。

二、小型四旋翼无人机动力学分析及数学建模

假设条件：

（1）视小型四旋翼无人机整体为刚体，且完全均匀对称；

（2）机体坐标原点与无人机的质心完全重合；

（3）无人机的螺旋桨为刚体，不考虑其结构和弹性形变。

（4）假设地面坐标系E为惯性坐标系。

线速度和角速度

举例：

想象一下，你和好朋友一起去游乐园坐旋转木马。

  • 你坐在紧靠边缘的木马上，
  • 你的朋友坐在靠近中心轴的木马上。

当木马转动起来时，你们俩的感受会完全不同：

  1. 转得快慢的感受（角速度）：你们俩转圈的节奏是一样的——木马转过一圈时，你们俩也同时转过一圈。在同一秒内，你们转过的“角度”是完全相同的。
  2. 迎面风速的感受（线速度）：如果你坐在边缘，你会觉得风呼呼地吹过，景物飞速倒退；而坐在中心的朋友，感觉相对平稳得多。因为在同样的时间里，你在外圈画了一个很大的圆，跑过的路程要比在内圈的朋友长得多！

角速度（$\omega$）—— 描述转动快慢

  • 通俗理解：单位时间内物体转过的角度。也就是“一秒钟转了多少度（或者多少弧度）”。

  • 理论定义：半径转过的角度 $\Delta \theta$ 与所用时间 $\Delta t$ 的比值。

  • 核心公式：

    $$\omega = \frac{\Delta \theta}{\Delta t}$$

  • 单位：弧度每秒 ($\text{rad/s}$)。

  • 特点：在刚体（如整个旋转木马、转盘）做同轴转动时，上面所有点的角速度都是完全相同的。

线速度（$v$）—— 描述空间位移快慢

  • 通俗理解：如果把圆周运动的轨迹“拉直”成一条直线，物体沿这条直线跑的速度就是线速度。它是一个矢量，方向永远沿着圆周的切线方向。

  • 理论定义：质点通过的弧长 $\Delta s$ 与所用时间 $\Delta t$ 的比值。

  • 核心公式：

    $$v = \frac{\Delta s}{\Delta t}$$

  • 单位：米每秒 ($\text{m/s}$)。

  • 特点：离转动中心越远（半径 $r$ 越大），相同的角速度下，跑的弧长就越长，因此线速度就越大。

既然角速度描述“转得快慢”，线速度描述“跑得有多快”，它们之间究竟有什么数学关系呢？

根据圆弧长公式 $\Delta s = r \cdot \Delta \theta$，我们代入线速度的定义：

$$v = \frac{\Delta s}{\Delta t} = \frac{r \cdot \Delta \theta}{\Delta t} = r \cdot \left(\frac{\Delta \theta}{\Delta t}\right)$$

因为 $\omega = \frac{\Delta \theta}{\Delta t}$，所以我们得到了一个极其重要的核心公式：

$$v = \omega r$$

问题一：四旋翼无人机的螺旋桨的转速指的是角速度么？

在工程实践中，我们常说电机或螺旋桨的转速是 $n$ (单位：转/分钟，RPM)。而在物理学和控制算法中，我们通常将其转化为角速度 $\omega$ (单位：弧度/秒，$\text{rad/s}$)。

它们之间的数学换算非常简单：$$\omega = \frac{2\pi n}{60}$$

所以，无论是无人机飞控固件（如 PX4/ArduPilot）底层代码里计算姿态控制，还是在动力学建模中，所谓的“转速指令”本质上就是给电机设定的角速度。

动力学分析

问题二：如何理解在进行无人机姿态仿真或研究无人机动力学原理的时候会“假设地面坐标系E为惯性坐标系”？

从经典力学的绝对严格定义来看，惯性坐标系要求坐标系本身处于静止或匀速直线运动状态，不转动也不加速。但我们身处的地面坐标系实际上附着在地球上，而地球存在两种运动：绕地轴自转和绕太阳公转。如果以宇宙中真正绝对静止的惯性系来看，地面坐标系是一个旋转的非惯性系。这意味着，严格在地面系中应用牛顿定律时，必须引入两种惯性力（或称虚拟力）：惯性离心力和科里奥利力。在绝大多数中小型无人机（如四旋翼、固定翼）的飞行工况下，地球自转产生的虚拟力与无人机自身的动力学加速度相比，小到完全可以忽略不计。如果不能把地面系当作惯性系，动力学建模的复杂度会呈指数级上升。

  1. 地面导航坐标系（$N$系，North-East-Down）：
    • $X$ 轴指向正北方 ($N$)
    • $Y$ 轴指向正东方 ($E$)
    • $Z$ 轴指向地心向下 ($D$)
    • 这是一个被我们假设为惯性系的绝对参考舞台。
  2. 机体坐标系（$B$系，Body Frame）：
    • 原点在无人机质心。
    • $X_b$ 轴指向机头前方。
    • $Y_b$ 轴指向机身右侧。
    • $Z_b$ 轴指向机腹下方。
    • 这个坐标系死死固定在无人机上，跟着它一起翻滚、俯仰。

我们的目标是：如果我知道一个向量在机体坐标系下的数值（比如传感器测出来的加速度、或者螺旋桨产生的推力方向），怎样通过一个数学矩阵，把它精准转换到地面导航坐标系下？这个矩阵记作 $C_b^n$（表示从 Body 到 Navigation 的转换矩阵）。

标准的机体坐标系到地面系方向余弦矩阵 $C_b^n$(具体的推导会单独写一篇博客，这里直接引用)：

$C_b^n = \begin{bmatrix} \cos\theta\cos\psi & \sin\phi\sin\theta\cos\psi - \cos\phi\sin\psi & \cos\phi\sin\theta\cos\psi + \sin\phi\sin\psi \\ \cos\theta\sin\psi & \sin\phi\sin\theta\sin\psi + \cos\phi\cos\psi & \cos\phi\sin\theta\sin\psi - \sin\phi\cos\psi \\ -\sin\theta & \sin\phi\cos\theta & \cos\phi\cos\theta \end{bmatrix}$

(注：式中 $\phi$ 为横滚 Roll，$\theta$ 为俯仰 Pitch，$\psi$ 为偏航 Yaw) 此处省略了它的推导。

问题三：好多论文中z轴方向是向上的？

在三维空间中，绝大多数学术论文、数学推导和三维引擎（如 OpenGL、ROS、MATLAB）都严格遵循右手笛卡尔坐标系。

在这个体系中，大拇指、食指和中指分别代表 $X、Y、Z$ 轴：

  1. 当你确定了 $X$ 轴的方向（如图中机体坐标系 $B$ 的 $x$ 指向右侧）。
  2. 当你由于直观需要，把 $Z$ 轴设定为向上（因为人类对高度的直觉就是“往上为正”）。
  3. 此时，为了满足数学上严格的叉乘关系（即 $X \text{轴} \times Y\text{轴} = Z\text{轴}$），你的 $Y$ 轴就别无选择，必须指向左边。

如果 $Y$ 轴敢指向右边，整个坐标系就会变成“左手系”，这会导致矩阵变换、叉乘运算和旋转四元数的数学公式全部出现符号错误。

结合空气动力学和螺旋桨知识可将螺旋桨的推力Ｔ、空气阻力ｆ、螺旋桨的转矩Ｍ 和阻力矩τ分别表示为

$\begin{cases} T=K_T\Omega^2 \\ f=K_f\dot{S} \\ M=K_M\Omega^2 \\ \tau=K_{\tau}\dot{ζ} \end{cases}$

其中：$Ｋ_T$表示螺旋桨推力系数；Ω 表示螺旋桨的转速；$Ｋ_f$表示空气阻力系数；$\dot{S}$ 表示线速度；$Ｋ_M$表示螺旋桨的转矩系数；$Ｋ_{\tau}$表示空气的阻力矩系数；$\dot{ζ}$表示角速度。

根据受力分析可得到机体坐标系下无人机整体升力$\mathbf{F}_B$为

$\begin{cases} \mathbf{F}_B=[F_x, F_y, F_z]^T=[0, 0, U_1]^T \\ U_1=\sum\limits^4_{i=1}T_i \\ T_i=K_T{\Omega}_i^2\end{cases}$

其中：ｉ表示表示相应的旋翼。

**空间位置运动学与动力学（平动方程），描述无人机在惯性坐标系下的空间三维位置(x,y,z)变化。**利用坐标转换矩阵将$\mathbf{F}_B$转换到地面坐标系下，得到$\mathbf{F}_E$

$\mathbf{F}_E=[F_X, F_Y, F_Z]^T=C_b^n\mathbf{F}_B=\begin{bmatrix} (cos{\phi}sin{\theta}cos{\psi}+sin{\phi}sin{\psi})U_1 \\ (cos{\phi}sin{\theta}cos{\psi}-sin{\phi}sin{\psi})U_1 \\ cos{\phi}cos{\theta}U_1 \end{bmatrix}$

在地面坐标系下，无人机所受的干扰力和重力可表示为

$\begin{cases} \mathbf{f_E}=\begin {bmatrix}f_X \ f_Y \ f_Z \end{bmatrix} = \begin {bmatrix}K_{fX}\dot{x} \\ K_{fY}\dot{y} \\ K_{fZ}\dot{z} \end{bmatrix} \\ \mathbf{G}_E=[0 \ 0 \ mg] \end{cases}$

在地面坐标下，根据牛顿第二定理$F=ma$

$m[\ddot{x} \ \ddot{y}\ \ddot{z}]^T = \mathbf{F}_E-\mathbf{f}_E-\mathbf{G}_E$

绕三个轴的力矩平衡方程：

$\begin{cases} I_x \dot{p} = U_2 + (I_y - I_z)qr - \tau_x \\ I_y \dot{q} = U_3 + (I_z - I_x)pr - \tau_y \\ I_z \dot{r} = U_4 + (I_x - I_y)pq - \tau_z \end{cases}$

其中：$Ｉ_x$、$Ｉ_y$、$Ｉ_z$分别表示机体绕三轴的转动惯性；ｐ、ｑ、ｒ分别表示无人机相对于机体坐标系的旋转角速度；${\tau}_x$、${\tau}_y$、${\tau}_z$分别表示空气对无人机在三轴方向上的阻力矩。这三行分别对应无人机的三个旋转方向：滚转轴（Roll）、俯仰轴（Pitch）和偏航轴（Yaw）。

以第一行（滚转轴方程）为例：我要让无人机滚转加速（$I_x \dot{p}$），取决于三个因素：我自己用电机制造的力矩（$U_2$） 减去空气的阻力（$\tau_x$），再加上由于多轴同时旋转带来的物理干扰（$(I_y - I_z)qr$）。

  • $I_x \dot{p}$

$I_x$：就是我们刚学过的转动惯量（绕 $x$ 轴的“旋转懒惰度”）。

$\dot{p}$：是滚转角加速度（代表滚转速度变化的快慢，也就是越转越快的加速度）。

$I_x \dot{p}$ 的物理意义：“懒惰程度 $\times$ 加速度”。这跟牛顿第二定律里的 $m \cdot a$ 简直一模一样！它代表了为了让无人机改变当前的旋转状态，你必须要克服的惯性阻力。

  • $U_2$

$U_2$：是四个螺旋桨通过差动（左边转得慢、右边转得快）人为制造出来的滚转控制力矩

  • $(I_y - I_z)qr$

$q$ 和 $r$分别是俯仰和偏航方向的转速。当无人机在空中极其灵活地同时进行几个方向的旋转时（比如既在向左倾斜，又在抬头或转头），旋转的物理规律会导致不同轴之间产生互相“拉扯”的附加力矩。

  • $\tau_x$

$\tau_x$：代表空气对旋转的黏滞阻力矩。

三个姿态控制力矩$U_2, U_3, U_4$

$\begin{cases} U_2 = (T_4 - T_2)L \\ U_3 = (T_3 - T_1)L \\ U_4 = K_M (\Omega_1^2 + \Omega_3^2 - \Omega_2^2 - \Omega_4^2) \end{cases}$

其中：Ｌ 是旋翼中心到机体重心之间的距离。

机体坐标系下的角速度$[p,q,r]^T$与地面坐标下的角速度$[\dot{\phi}, \dot{\theta}, \dot{\psi}]^T$之间关系为(具体的推导会单独写一篇博客，这里直接引用)

$\begin{bmatrix}p \\ q \\ r \end{bmatrix} = \begin{pmatrix} 1 & 0 & -sin{\theta} \\ 0 & cos{\phi} & sin{\phi}cos{\theta} \\ 0 & -sin{\phi} & cos{\phi}cos{\theta} \\ \end{pmatrix} \begin{bmatrix} \dot{\phi} \\ \dot{\theta} \\ \dot{\psi} \end{bmatrix}$

在小角度情况下，$[p,q,r]^T$可近似为$[\dot{\phi}, \dot{\theta}, \dot{\psi}]^T$，即：

$[p,q,r]^T=[\dot{\phi}, \dot{\theta}, \dot{\psi}]^T$

因此，机体角速度动力学（转动方程），描述机体坐标系下的三轴角速度(p,q,r)如何在控制力矩和惯性耦合下变化。地面坐标系下的角加速度为

$\begin{cases} \ddot{\phi} = [U_2+(I_y-I_z)\dot{\theta}\dot{\psi}-K_{{\tau}X}\dot{\phi}]/I_x \\ \ddot{\theta} = [U_3+(I_z-I_x)\dot{\phi}\dot{\psi}-K_{{\tau}Y}\dot{\theta}]/I_y \\ \ddot{\psi} = [U_4+(I_x-I_y)\dot{\phi}\dot{\theta}-K_{{\tau}Z}\dot{\psi}]/I_z \end{cases}$

在该动力学模型中$(\ddot{x},\dot{y},\ddot{z},\ddot{\phi},\ddot{\theta},\ddot{\psi})$是关于变量的数学表达式，即表示无人机的位姿变化是由四个旋翼的转速来控制的。

$ \begin{cases} \ddot{x}=[(cos{\phi}sin{\theta}cos{\psi}+sin{\phi}sin{\psi})U_1-K_{fX}\dot{x}]/m \\ \ddot{y}=[(cos{\phi}sin{\theta}cos{\psi}-sin{\phi}sin{\psi})U_1-K_{fY}\dot{y}]/m \\ \ddot{z}=[(cos{\phi}cos{\theta}U_1-K_{fZ}\dot{z}-mg]/m\\ \ddot{\phi} = [U_2+(I_y-I_z)\dot{\theta}\dot{\psi}-K_{ {\tau}X }\dot{\phi}]/I_x \\ \ddot{\theta} = [U_3+(I_z-I_x)\dot{\phi}\dot{\psi}-K_{ {\tau}Y }\dot{\theta}]/I_y \\ \ddot{\psi} = [U_4+(I_x-I_y)\dot{\phi}\dot{\theta}-K_{ {\tau}Z }\dot{\psi}]/I_z \end{cases} $

NVIDIA Jetson AGX Orin 算法部署流程

一、Jetson AGX Orin

1.1、介绍

Jetson AGX Orin 是 NVIDIA Jetson 边缘计算家族中的旗舰级产品（Top-tier Flagship），专为对实时性要求极高、计算复杂度极大、需要处理多路高分辨率传感器数据的边缘 AI 场景（如高阶自动驾驶、复杂机器人控制、无人机三维建图、边缘端多模态/大模型推理）而设计。如果说 Orin 架构是一套高性能引擎，那么 Jetson AGX Orin 则是将这套架构发挥到极致的“性能怪兽”。

1.2、 核心优势

  1. 真正的“零拷贝”（Zero-Copy）统一内存架构

AGX Orin 的 CPU、GPU 以及硬件解码器共享高带宽的 LPDDR5 统一内存。在进行多路图像/点云处理时，从摄像头读取数据、解码、上传到 GPU 推理、再到渲染输出，全程无需在 CPU RAM 和 GPU 显存之间进行繁重的内存拷贝，大大降低了端到端延迟。

  1. 双 DLA 与 GPU 异构并行计算

AGX Orin 拥有 2 个独立的 DLA（Deep Learning Accelerator）引擎。在实际部署中，你可以把主干目标检测模型（如 YOLO）扔给 GPU 运行，而把辅助模型（如车道线识别、人脸关键点检测）剥离给 DLA。这样可以在不占用 GPU 算力的前提下，实现多模型并行高效运行。

  1. 支持复杂的“传感器融合”与大模型

凭借 64GB 的大内存与 275 TOPS 算力，AGX Orin 不仅能轻松应对多路 1080p 视频的目标检测与追踪，还能够直接在本地跑通激光雷达（LiDAR）与可见光相机的 3D 点云传感器融合建图、实时 SLAM 导航，甚至能在边缘端本地部署百亿参数级别的微型大语言模型（LLM）与 VLM 视觉大模型。

二、TensorRT

TensorRT 是 NVIDIA 推出的一个高性能深度学习推理优化器和运行时引擎。它专门针对 NVIDIA 的 GPU（如你手中的 Jetson AGX Orin 或桌面显卡）进行极致的底层优化，让训练好的神经网络模型在部署时跑得更快、吞吐更高、延迟更低。

在工程实践中，TensorRT 能够成倍提升推理性能，主要依靠以下四大核心技术：

  1. 算子融合（Layer Fusion）
  • 原理：在深度学习框架中（如 PyTorch），像 Conv（卷积） + BatchNorm（归一化） + ReLU（激活函数） 是三个独立的计算层。在前向推理时，数据需要先写入显存、从显存读出做 Conv、再写回显存、再读出来做 BN……这会产生大量的显存带宽浪费（Memory Bound）。
  • TensorRT 优化：TensorRT 会自动扫描计算图，将这些相邻的算子“熔铸”成一个单一的复合内核（Kernel）。数据只需在 GPU 寄存器或片上缓存中流转一次就完成全部计算，大幅减少了显存访存开销。
  1. 精度校准与量化（Precision Calibration & Quantization）
  • 原理：深度学习模型在训练时通常使用 FP32（32位单精度浮点数）。但在实际边缘端推理中，绝大多数神经网络并不需要如此高的精度。
  • TensorRT 优化：
    • FP16 半精度：利用 Orin 等现代 GPU 硬件上专用的 Tensor Cores，FP16 计算速度是 FP32 的数倍，且模型体积减半，精度几乎无损。
    • INT8 量化：将权重和激活值压缩为 8 位整数。TensorRT 提供了强大的熵校准（Entropy Calibration）算法，在几乎不损失模型准确率（mAP）的前提下，将推理吞吐量推向极致，并大幅降低内存占用。
  1. 内核自动调优（Kernel Auto-Tuning）
  • 原理：针对不同的硬件平台（如 Jetson AGX Orin 的 Ampere GPU 架构与 RTX 3060 Ti），最优的矩阵乘法或卷积实现算法是完全不同的。
  • TensorRT 优化：在将 ONNX 转换为 .engine 文件的编译阶段（这一步通常比较耗时），TensorRT 会针对当前硬件的 CUDA 核心数量、SM（Streaming Multiprocessor）架构、共享内存大小，对模型中的每一个计算层测试几十种不同的底层 CUDA 实现算法，最终挑选出执行速度最快的那一个“最优解”。
  1. 动态显存管理（Dynamic Memory Management）
  • 原理：推理过程中，中间张量（Intermediate Tensors）的临时显存分配和释放会带来不小的开销。
  • TensorRT 优化：TensorRT 在编译时会进行全局生命周期分析，精确计算并复用显存空间，确保整个推理流水线中显存占用最小化、碎片化最低。

三、NVIDIA JetPack SDK

NVIDIA JetPack SDK 是 NVIDIA 专为 Jetson 系列边缘计算硬件（如你手中的 Jetson AGX Orin）打造的官方集成软件开发包（Software Development Kit）。如果把 Jetson Orin 硬件比作一台性能强劲的超跑，那么 JetPack 就是让这台超跑能够上路狂飙的整套“汽车操作系统、发动机控制固件以及专业驾驶辅助软件”。

下面我们同样从通俗比喻和专业理论两个角度来剖析 JetPack 的本质与作用：

3.1、 通俗角度：把一堆散装零件变成“智能机器人大脑”

想象一下，你刚买回来的 Jetson AGX Orin 裸板，上面只有密密麻麻的芯片、GPU、CPU 和各种接口。此时它就像一辆刚从工厂下线的赛车，空有一身好力气，却连方向盘和油门都不知道怎么踩——操作系统还没装，GPU 怎么调用也不知道。

JetPack 的作用，就是把所有这些杂乱的底层硬件和上层 AI 算法完美缝合在一起的一键式“精装修包”：

  1. 铺路架桥（操作系统）：它把深度定制的 Ubuntu 系统装进芯片，让你可以像用普通电脑一样连鼠标、键盘、输命令。
  2. 打通经脉（底层驱动）：它写好了让 CPU、GPU、DLA（深度学习加速器）和摄像头接口协同工作的底层驱动，防止硬件“各自为战”。
  3. 装备武器（AI 工具链）：它把 TensorRT、CUDA 等一整套大杀器直接打包好。你不需要自己去一行行配置复杂的显卡驱动，装上 JetPack，你的硬件就已经具备了运行最前沿 AI 算法的能力。

3.2、 专业理论角度：全栈式异构计算软件架构

在工程与理论层面，JetPack 并不是一个单一的软件，而是一个分层、解耦的异构计算软件栈（Software Stack）。它自底向上主要由以下几个核心层级构成：

3.2.1. 操作系统层（L4T: Linux for Tegra）

  • 理论核心：基于 Ubuntu LTS（如 JetPack 5 对应 Ubuntu 20.04，JetPack 6 对应 Ubuntu 22.04）深度定制的 Linux 内核。
  • 工程作用：针对 Tegra 芯片的电源管理（NVPModel）、热管理（Thermal Management）、PCIe、USB 和硬件 GPIO 进行了底层特化，确保边缘设备在复杂恶劣的工业或车载环境下稳定运行。

3.2.2. 加速计算与驱动层（CUDA-X & Libraries）

  • 理论核心：
    • CUDA / cuDNN：让开发者能够直接调度 Ampere 架构 GPU 内部的数千个并行核心和 Tensor Cores。
    • VPI (Vision Programming Interface)：专为传统计算机视觉算法（如几何变换、滤波、光流）设计的硬件加速库，将任务分流给 PVA（可编程视觉加速器）处理。
  • 工程作用：实现软硬件的极致解耦。算法工程师无需编写复杂的底层汇编或直接操作寄存器，只需调用标准 API 即可榨干硬件算力。

3.2.3. AI 推理与应用框架层（TensorRT & DeepStream）

  • 理论核心：
    • TensorRT：前文提到的核心推理优化引擎，负责模型的图优化、算子融合与量化。
    • DeepStream SDK：基于 GStreamer 的多路视频流分析框架。它在理论上实现了“零拷贝（Zero-Copy）”流水线——从摄像头采集图像、硬件解码（NVDEC）、TensorRT 推理到最终渲染，数据全程在 GPU 统一内存中流转，彻底消除了传统 CPU-GPU 内存搬运的带宽瓶颈。

RK3855介绍

RK3588 是瑞芯微（Rockchip）推出的一款旗舰级级 AIoT（智能物联网）芯片。基于它打造的开发板（如香橙派 Orange Pi 5 Plus、讯为 RK3588、Firefly ROC-RK3588S 等），凭借极其强悍的性能和丰富的接口，被开发者们称为“微型服务器”或“ARM 性能怪兽”。

CPU、GPU、NPU三者的区别是什么？

  1. CPU（中央处理器）：全能的“大班长”
  • 特点： 少而精，擅长复杂逻辑。
  • 原理： CPU 的核心数量很少（通常只有几个到十几个），但每个核心的实力都极其强悍。它配备了大量的控制单元和缓存，能够处理极度复杂的条件判断（如果……就……否则……）和突发任务。它是整台设备的“大脑”和总调度官。
  1. GPU（图形处理器）：暴力的“人海战术”
  • 特点： 多而简单，擅长并行计算。
  • 原理： GPU 拥有成百上千甚至上万个微型核心。虽然每个核心的单独算力远不如 CPU 强大，甚至只能做简单的加减乘除，但它们可以同时开工。这种为了同时处理海量简单数据的结构，被称为“并行计算”。
  1. NPU（网络处理器 / AI 芯片）：纯粹的“偏科天才”
  • 特点： 专机专用，专门为了“矩阵乘法”而生。
  • 原理： NPU 抛弃了 CPU 复杂的逻辑控制，也抛弃了 GPU 复杂的图像渲染管线。它的硬件电路是专门为了深度学习中的卷积、矩阵乘法和激活函数量身定制的。数据像流水一样经过它固定的计算阵列，就能以极低的功耗、极快的速度完成 AI 推理。

在 RK3588 上运行一个实际的 AI 项目，例如：用摄像头实时检测进出房间的人脸时，这三者绝不是单打独斗，而是高度协同的流水线：

[摄像头输入] ──> (CPU: 抓取与缩放) ──> (NPU: 特征提取/人脸识别) ──> (GPU: 渲染框与UI) ──> [显示器输出]

  1. RK3588 的 CPU（4×A76 + 4×A55）在做什么？
  • 作用： 主导全局、数据前后处理。
  • 操作系统（如 Ubuntu）本身就跑在 CPU 上。当摄像头拍到画面时，CPU 负责把图像数据抓取进来，进行解码、裁剪、缩放（前处理），然后下达命令给 NPU：“数据准备好了，你来算人脸特征”。当 NPU 算完后，CPU 还要负责业务逻辑（比如：判断这个人是不是白名单里的员工，是的话就发送信号控制警报器或开门）。
  1. RK3588 的 NPU（3核共 6 TOPS）在做什么？
  • 作用： 纯粹的 AI 模型推理加速。
  • 它是你跑 yolov5.rknn 或人脸识别网络时的核心发动机。CPU 传过来的图像数据，进入 NPU 后，被瞬间塞进 6 TOPS 算力的矩阵计算阵列中。原本如果用 CPU 跑需要 200 毫秒的面部特征提取，NPU 只需要几毫秒就能搞定，并且功耗极低，芯片不会发烫。
  1. RK3588 的 GPU（Mali-G610）在做什么？
  • 作用： 界面渲染与图形输出。
  • 当 NPU 识别出人脸并给出坐标后，GPU 负责把人脸周围的“绿色瞄准框”、文字标签以及系统的 GUI 界面，流畅地绘制并刷新在显示器上。如果你需要同时输出到两块屏幕，或者播放 4K/8K 视频，GPU 就会在幕后负责这些像素级的图形渲染工作。

  • RKNN Runtime 为 Rockchip NPU 平台提供 C/C++ 编程接口，帮助用户部署 RKNN 模型并加速 AI 应用的实现。

RKNN开发流程

RKNN的开发流程主要包括3部分：模型转换、模型评估和板端部署

1.模型转换：

原始的深度学习模型会被转化为RKNN格式，以便在RKNPU平台上进行高效的推理。这一阶段包括以下5个步骤：
a. 获取原始模型：获取或训练深度学习模型，建议使用主流框架，如ONNX、PyTorch或TensorFlow。
b. 模型配置：在RKNN-Toolkit2中进行必要的配置，如归一化参数、量化参数和目标平台等。
c. 模型加载：使用适当的加载接口将模型导入RKNN-Toolkit2，根据模型框架选择正确的加载接口。
d. 模型构建：通过rknn.build() 接口构建RKNN模型，可选择是否进行量化，提高模型在硬件上推理的性能。
e. 模型导出：通过rknn.export_rknn() 接口将RKNN模型导出成一个文件（.rknn 格式），用于后续部署。

2.模型评估：

该阶段的主要目标是评估模型推理结果的准确性、推理性能和内存占用等关键指标。评估的主要步骤如下：
a. 模型连板调试：使用Python连接RKNPU平台对模型进行推理并验证结果准确性。这个阶段涵盖了输入数据的前处理和输出结果的后处理，以确保模型在板上运行正确。
b. 精度评估：通过rknn.accuracy_analysis() 接口，比较量化模型与浮点模型推理结果之间的差异，以分析量化误差的来源。
c. 性能评估：通过rknn.eval_perf() 接口，分析模型在RKNPU平台上的推理性能，帮助用户进一步优化模型结构，加快推理性能。
d. 内存评估：通过rknn.eval_memory() 接口，了解模型在RKNPU平台上的内存使用情况，帮助用户进一步优化模型结构，最小化内存占用。

3.板端部署：

这个阶段涵盖了模型的实际部署和运行。它通常包括以下步骤：
a. 模型初始化：加载RKNN模型到RKNPU平台，准备进行前处理。
b. 模型前处理：加载待推理数据到RKNPU平台，准备进行推理。
c. 模型推理：执行推理操作，将输入数据传递给模型并获取推理结果。
d. 模型后处理：获取推理结果进行后处理，后处理结果传给应用端。
e. 模型释放：在完成推理流程后，释放模型资源，以便其他任务使用RKNN模型。

什么是智能体？

发表于 2026-06-19 更新于 2026-07-01 分类于 大模型和智能体

智能体（Agent）

定义：

在人工智能领域，智能体 (Agent) 是指一个能够自主感知环境、进行思考推理，并采取行动以实现特定目标的计算系统。

Agent = LLM (大脑) + Planning (规划) + Memory (记忆) + Tools (工具)

核心原理：

大模型本身只是一个“下一个词预测器”，它没有主动性。而 Agent 是给大模型套上了一个运行循环（Loop），使其具备以下四个要素：

  1. 感知（Perception）：接收用户的指令、网页输入或传感器数据。
  2. 大脑（LLM / Planning）：通过 Prompt 工程（如 ReAct 框架、CoT 思维链）让大模型分析现状，决定“下一步该做什么”，并把大任务拆解为小任务。
  3. 记忆（Memory）：
    • 短期记忆：当前的对话上下文、执行步骤。
    • 长期记忆：通过向量数据库（RAG）读取历史经验或外部知识。
    • 行动（Action）：调用外部工具去执行任务（比如查数据库、发邮件、跑代码）。

通俗解释：

普通大模型是“懂很多理论的军师”，你问它什么它都能答，但它自己没办法去办；而 Agent 是“有手有脚的特工 / 助理”，你给它一个目标，它会自己想办法去完成。

案例：

你对 Agent 说：“帮我订一张下周二去北京最便宜的机票。”

Agent 的思考过程：

  1. （规划）我需要先查今天几号，再查下周二的日期。
  2. （行动/工具）调用“日历工具”发现下周二是个公历日期。
  3. （行动/工具）调用“机票API”查询所有航班和价格。
  4. （思考）比对后发现 A 航班最便宜。
  5. （行动/工具）调用“支付/订票API”为你锁定机票，并发送确认短信（或生成付款链接）。

MCP (Model Context Protocol, 模型上下文协议)

定义：

MCP（模型上下文协议） 是一个开放的标准协议，它允许开发者构建安全的、双向的通道，使大模型（LLM）能够无缝连接到数据源（如数据库、文件系统）和开发工具（如 IDE）。

原理：

在 MCP 出现之前，如果想让大模型读你的 GitHub 仓库、查你的 Postgres 数据库，每个开发者都要自己写一套对接代码（即硬编码的 Tool Calling）。 MCP 效仿了互联网时代的 HTTP 协议 或开发领域的 LSP（语言服务器协议），提出了一个统一的架构：

  • MCP 客户端 (Client)：大模型应用（如 Claude Desktop、Cursor、智能体框架）。
  • MCP 服务端 (Server)：各种数据源或工具的适配器（如 GitHub MCP Server、Slack MCP Server、Postgres MCP Server）。 只要大家都遵守 MCP 协议，大模型就能像插上 USB 闪存盘一样，即插即用地访问任何支持该协议的外部数据和工具。

通俗解释：

MCP 就像是电子设备的 USB-C 统一接口。以前每款手机、电脑都有自己的充电口和数据线（各种定制 API 接口），乱成一团。有了 USB-C（MCP），不管你是接鼠标、U盘还是显示器，一根线插上就能用。

案例：

你使用一个支持 MCP 的 AI 编辑器（Client），它通过 MCP Postgres Server 直接读取了你本地数据库的表结构，又通过 MCP Git Server 读取了你的代码提交记录。你只需说一句：“帮我优化这个查询”，AI 就能同时看完数据库和代码，直接把改好的代码提交上去。

Skills (技能)

定义：

在大模型和智能体生态中，Skills（技能） 是指封装好的、高层级的、可复用的特定功能模块或任务执行能力。它通常由一段特定逻辑的代码、一组 Prompt 提示词以及定义好的输入输出接口（API）组合而成。

原理：

如果说大模型拥有“通用智商”，那么 Skills 就是它后天学习到的“专业技能证书”。 在大模型内部，Skills 的本质是 Tool Calling（工具调用）或 Function Calling（函数调用）的一种高级封装。

  1. 技能描述（Manifest）：用自然语言写明“这个技能是干什么的，需要什么参数”。大模型就是通过阅读这段描述，来判断什么时候该调用这个技能。
  2. 执行逻辑（Execution）：技能背后的实体，可以是一段 Python 代码、一个现成的 Web API（比如天气预报接口），甚至是一个子 Agent。

通俗解释：

大模型就像是一个“刚毕业的大学生”，智商很高，但什么具体的活都不会。你给它安装了一个“Excel 高级图表技能包”，它就立刻学会了怎么把数据变成折线图。

案例：

你在 Coze 平台上搭建一个“小红书爆款文案 Agent”，你可以给它配置三个 Skills：

  • 技能 A：【爆款爬取】自动抓取当前某个话题下点赞最高的 10 篇帖子。
  • 技能 B：【风格模仿】将任意文字一键转换成带有大量表情符号（Emoji）的小红书网感文案。
  • 技能 C：【配图生成】根据文案内容，自动调用 Midjourney 接口生成一张 3:4 的配图。 当用户输入一个主题时，Agent 就会依次调用这三个 Skill 来交付最终成果。

三者如何协作开展工作的？

用户向 Agent 下达任务。Agent 通过 MCP 协议安全地读取了你电脑里的工作文档（连接了上下文），接着它发现需要分析数据，于是调用了自己携带的“数据可视化 Skill”，最后把完美的图表生成并保存到了你的本地文件夹中。
