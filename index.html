NVIDIA Jetson AGX Orin 算法部署流程

发表于 2026-11-04 分类于 边缘端部署

一、Jetson AGX Orin

1.1、介绍

Jetson AGX Orin 是 NVIDIA Jetson 边缘计算家族中的旗舰级产品（Top-tier Flagship），专为对实时性要求极高、计算复杂度极大、需要处理多路高分辨率传感器数据的边缘 AI 场景（如高阶自动驾驶、复杂机器人控制、无人机三维建图、边缘端多模态/大模型推理）而设计。如果说 Orin 架构是一套高性能引擎，那么 Jetson AGX Orin 则是将这套架构发挥到极致的“性能怪兽”。

1.2、 核心优势

  1. 真正的“零拷贝”（Zero-Copy）统一内存架构

AGX Orin 的 CPU、GPU 以及硬件解码器共享高带宽的 LPDDR5 统一内存。在进行多路图像/点云处理时，从摄像头读取数据、解码、上传到 GPU 推理、再到渲染输出，全程无需在 CPU RAM 和 GPU 显存之间进行繁重的内存拷贝，大大降低了端到端延迟。

  1. 双 DLA 与 GPU 异构并行计算

AGX Orin 拥有 2 个独立的 DLA（Deep Learning Accelerator）引擎。在实际部署中，你可以把主干目标检测模型（如 YOLO）扔给 GPU 运行，而把辅助模型（如车道线识别、人脸关键点检测）剥离给 DLA。这样可以在不占用 GPU 算力的前提下，实现多模型并行高效运行。

  1. 支持复杂的“传感器融合”与大模型

凭借 64GB 的大内存与 275 TOPS 算力，AGX Orin 不仅能轻松应对多路 1080p 视频的目标检测与追踪，还能够直接在本地跑通激光雷达（LiDAR）与可见光相机的 3D 点云传感器融合建图、实时 SLAM 导航，甚至能在边缘端本地部署百亿参数级别的微型大语言模型（LLM）与 VLM 视觉大模型。

二、TensorRT

TensorRT 是 NVIDIA 推出的一个高性能深度学习推理优化器和运行时引擎。它专门针对 NVIDIA 的 GPU（如你手中的 Jetson AGX Orin 或桌面显卡）进行极致的底层优化，让训练好的神经网络模型在部署时跑得更快、吞吐更高、延迟更低。

在工程实践中，TensorRT 能够成倍提升推理性能，主要依靠以下四大核心技术：

  1. 算子融合（Layer Fusion）
  • 原理：在深度学习框架中（如 PyTorch），像 Conv（卷积） + BatchNorm（归一化） + ReLU（激活函数） 是三个独立的计算层。在前向推理时，数据需要先写入显存、从显存读出做 Conv、再写回显存、再读出来做 BN……这会产生大量的显存带宽浪费（Memory Bound）。
  • TensorRT 优化：TensorRT 会自动扫描计算图，将这些相邻的算子“熔铸”成一个单一的复合内核（Kernel）。数据只需在 GPU 寄存器或片上缓存中流转一次就完成全部计算，大幅减少了显存访存开销。
  1. 精度校准与量化（Precision Calibration & Quantization）
  • 原理：深度学习模型在训练时通常使用 FP32（32位单精度浮点数）。但在实际边缘端推理中，绝大多数神经网络并不需要如此高的精度。
  • TensorRT 优化：
    • FP16 半精度：利用 Orin 等现代 GPU 硬件上专用的 Tensor Cores，FP16 计算速度是 FP32 的数倍，且模型体积减半，精度几乎无损。
    • INT8 量化：将权重和激活值压缩为 8 位整数。TensorRT 提供了强大的熵校准（Entropy Calibration）算法，在几乎不损失模型准确率（mAP）的前提下，将推理吞吐量推向极致，并大幅降低内存占用。
  1. 内核自动调优（Kernel Auto-Tuning）
  • 原理：针对不同的硬件平台（如 Jetson AGX Orin 的 Ampere GPU 架构与 RTX 3060 Ti），最优的矩阵乘法或卷积实现算法是完全不同的。
  • TensorRT 优化：在将 ONNX 转换为 .engine 文件的编译阶段（这一步通常比较耗时），TensorRT 会针对当前硬件的 CUDA 核心数量、SM（Streaming Multiprocessor）架构、共享内存大小，对模型中的每一个计算层测试几十种不同的底层 CUDA 实现算法，最终挑选出执行速度最快的那一个“最优解”。
  1. 动态显存管理（Dynamic Memory Management）
  • 原理：推理过程中，中间张量（Intermediate Tensors）的临时显存分配和释放会带来不小的开销。
  • TensorRT 优化：TensorRT 在编译时会进行全局生命周期分析，精确计算并复用显存空间，确保整个推理流水线中显存占用最小化、碎片化最低。

三、NVIDIA JetPack SDK

NVIDIA JetPack SDK 是 NVIDIA 专为 Jetson 系列边缘计算硬件（如你手中的 Jetson AGX Orin）打造的官方集成软件开发包（Software Development Kit）。如果把 Jetson Orin 硬件比作一台性能强劲的超跑，那么 JetPack 就是让这台超跑能够上路狂飙的整套“汽车操作系统、发动机控制固件以及专业驾驶辅助软件”。

下面我们同样从通俗比喻和专业理论两个角度来剖析 JetPack 的本质与作用：

3.1、 通俗角度：把一堆散装零件变成“智能机器人大脑”

想象一下，你刚买回来的 Jetson AGX Orin 裸板，上面只有密密麻麻的芯片、GPU、CPU 和各种接口。此时它就像一辆刚从工厂下线的赛车，空有一身好力气，却连方向盘和油门都不知道怎么踩——操作系统还没装，GPU 怎么调用也不知道。

JetPack 的作用，就是把所有这些杂乱的底层硬件和上层 AI 算法完美缝合在一起的一键式“精装修包”：

  1. 铺路架桥（操作系统）：它把深度定制的 Ubuntu 系统装进芯片，让你可以像用普通电脑一样连鼠标、键盘、输命令。
  2. 打通经脉（底层驱动）：它写好了让 CPU、GPU、DLA（深度学习加速器）和摄像头接口协同工作的底层驱动，防止硬件“各自为战”。
  3. 装备武器（AI 工具链）：它把 TensorRT、CUDA 等一整套大杀器直接打包好。你不需要自己去一行行配置复杂的显卡驱动，装上 JetPack，你的硬件就已经具备了运行最前沿 AI 算法的能力。

3.2、 专业理论角度：全栈式异构计算软件架构

在工程与理论层面，JetPack 并不是一个单一的软件，而是一个分层、解耦的异构计算软件栈（Software Stack）。它自底向上主要由以下几个核心层级构成：

3.2.1. 操作系统层（L4T: Linux for Tegra）

  • 理论核心：基于 Ubuntu LTS（如 JetPack 5 对应 Ubuntu 20.04，JetPack 6 对应 Ubuntu 22.04）深度定制的 Linux 内核。
  • 工程作用：针对 Tegra 芯片的电源管理（NVPModel）、热管理（Thermal Management）、PCIe、USB 和硬件 GPIO 进行了底层特化，确保边缘设备在复杂恶劣的工业或车载环境下稳定运行。

3.2.2. 加速计算与驱动层（CUDA-X & Libraries）

  • 理论核心：
    • CUDA / cuDNN：让开发者能够直接调度 Ampere 架构 GPU 内部的数千个并行核心和 Tensor Cores。
    • **VPI (Vision Programming Interface)**：专为传统计算机视觉算法（如几何变换、滤波、光流）设计的硬件加速库，将任务分流给 PVA（可编程视觉加速器）处理。
  • 工程作用：实现软硬件的极致解耦。算法工程师无需编写复杂的底层汇编或直接操作寄存器，只需调用标准 API 即可榨干硬件算力。

3.2.3. AI 推理与应用框架层（TensorRT & DeepStream）

  • 理论核心：
    • TensorRT：前文提到的核心推理优化引擎，负责模型的图优化、算子融合与量化。
    • DeepStream SDK：基于 GStreamer 的多路视频流分析框架。它在理论上实现了“零拷贝（Zero-Copy）”流水线——从摄像头采集图像、硬件解码（NVDEC）、TensorRT 推理到最终渲染，数据全程在 GPU 统一内存中流转，彻底消除了传统 CPU-GPU 内存搬运的带宽瓶颈。

四、部署流程

将模型（以YOLOv11为例）部署到NVIDIA Jetson AGX Orin上，核心流程遵循“PC端训练导出模型 —-> Orin端TensorRT编译 —-> 编写脚本推理”的标准链路。

RK3855介绍

RK3588 是瑞芯微（Rockchip）推出的一款旗舰级级 AIoT（智能物联网）芯片。基于它打造的开发板（如香橙派 Orange Pi 5 Plus、讯为 RK3588、Firefly ROC-RK3588S 等），凭借极其强悍的性能和丰富的接口，被开发者们称为“微型服务器”或“ARM 性能怪兽”。

CPU、GPU、NPU三者的区别是什么？

  1. CPU（中央处理器）：全能的“大班长”
  • 特点： 少而精，擅长复杂逻辑。
  • 原理： CPU 的核心数量很少（通常只有几个到十几个），但每个核心的实力都极其强悍。它配备了大量的控制单元和缓存，能够处理极度复杂的条件判断（如果……就……否则……）和突发任务。它是整台设备的“大脑”和总调度官。
  1. GPU（图形处理器）：暴力的“人海战术”
  • 特点： 多而简单，擅长并行计算。
  • 原理： GPU 拥有成百上千甚至上万个微型核心。虽然每个核心的单独算力远不如 CPU 强大，甚至只能做简单的加减乘除，但它们可以同时开工。这种为了同时处理海量简单数据的结构，被称为“并行计算”。
  1. NPU（网络处理器 / AI 芯片）：纯粹的“偏科天才”
  • 特点： 专机专用，专门为了“矩阵乘法”而生。
  • 原理： NPU 抛弃了 CPU 复杂的逻辑控制，也抛弃了 GPU 复杂的图像渲染管线。它的硬件电路是专门为了深度学习中的卷积、矩阵乘法和激活函数量身定制的。数据像流水一样经过它固定的计算阵列，就能以极低的功耗、极快的速度完成 AI 推理。

在 RK3588 上运行一个实际的 AI 项目，例如：用摄像头实时检测进出房间的人脸时，这三者绝不是单打独斗，而是高度协同的流水线：

[摄像头输入] ──> (CPU: 抓取与缩放) ──> (NPU: 特征提取/人脸识别) ──> (GPU: 渲染框与UI) ──> [显示器输出]

  1. RK3588 的 CPU（4×A76 + 4×A55）在做什么？
  • 作用： 主导全局、数据前后处理。
  • 操作系统（如 Ubuntu）本身就跑在 CPU 上。当摄像头拍到画面时，CPU 负责把图像数据抓取进来，进行解码、裁剪、缩放（前处理），然后下达命令给 NPU：“数据准备好了，你来算人脸特征”。当 NPU 算完后，CPU 还要负责业务逻辑（比如：判断这个人是不是白名单里的员工，是的话就发送信号控制警报器或开门）。
  1. RK3588 的 NPU（3核共 6 TOPS）在做什么？
  • 作用： 纯粹的 AI 模型推理加速。
  • 它是你跑 yolov5.rknn 或人脸识别网络时的核心发动机。CPU 传过来的图像数据，进入 NPU 后，被瞬间塞进 6 TOPS 算力的矩阵计算阵列中。原本如果用 CPU 跑需要 200 毫秒的面部特征提取，NPU 只需要几毫秒就能搞定，并且功耗极低，芯片不会发烫。
  1. RK3588 的 GPU（Mali-G610）在做什么？
  • 作用： 界面渲染与图形输出。
  • 当 NPU 识别出人脸并给出坐标后，GPU 负责把人脸周围的“绿色瞄准框”、文字标签以及系统的 GUI 界面，流畅地绘制并刷新在显示器上。如果你需要同时输出到两块屏幕，或者播放 4K/8K 视频，GPU 就会在幕后负责这些像素级的图形渲染工作。

RKNN工具链

要使用 RKNN-NPU，用户需要先在计算机上运行 RKNN-Toolkit2 工具，将训练好的模型转换为 RKNN 格式模型，然后使用 RKNN C API或 Python API 在开发板上进行推理。

  • RKNN-Toolkit2 是一个软件开发工具包，用于在 PC(Liunx系统上) 和 Rockchip NPU 平台上进行模型转换、推理和性能评估。
  • RKNN-Toolkit-Lite2 为 Rockchip NPU 平台提供 Python 编程接口，帮助用户部署 RKNN 模型并加速 AI 应用的实现。
  • RKNN Runtime 为 Rockchip NPU 平台提供 C/C++ 编程接口，帮助用户部署 RKNN 模型并加速 AI 应用的实现。
  • RKNPU 内核驱动程序负责与 NPU 硬件进行交互。该驱动程序已开源，可在 Rockchip 内核代码中找到。

通过该工具提供的Python接口可以便捷地完成以下功能：

  1. 模型转换：支持将PyTorch、ONNX、TensorFlow、TensorFlow Lite、Caffe、DarkNet等模型转为RKNN模型。

  6. 模型加密功能：使用指定的加密等级将RKNN模型整体加密。

RKNN Runtime

RKNN Runtime负责加载RKNN模型，并调用NPU驱动实现在NPU上推理RKNN模型。推理RKNN模型时，包括原始数据输入预处理、NPU运行模型、输出后处理三项流程。根据不同模型输入格式和量化方式，RKNN Runtime提供通用API和零拷贝API两种处理流程。

通用API推理：提供一套简洁、无门槛的推理API，易于使用，流程如下图所示。其中对数据的归一化、量化、数据排布格式转换、反量化等均在CPU上运行，模型本身的推理在NPU上运行。

零拷贝API推理：流程如下图所示。优化了通用API的数据处理流程，归一化、量化和模型推理都会在NPU上运行，NPU输出的数据排布格式和反量化过程在CPU或者NPU上运行。零拷贝API对于输入数据流程的处理效率会比通用API高。支持数据在不同的IP核之间流动，没有数据拷贝，减少CPU及DDR带宽消耗。比如通过camera或者解码出来的数据，支持零拷贝导入到NPU中使用。

RKNN开发流程

RKNN的开发流程主要包括3部分：模型转换、模型评估和板端部署

1.模型转换：

原始的深度学习模型会被转化为RKNN格式，以便在RKNPU平台上进行高效的推理。这一阶段包括以下5个步骤：
a. 获取原始模型：获取或训练深度学习模型，建议使用主流框架，如ONNX、PyTorch或TensorFlow。
b. 模型配置：在RKNN-Toolkit2中进行必要的配置，如归一化参数、量化参数和目标平台等。
c. 模型加载：使用适当的加载接口将模型导入RKNN-Toolkit2，根据模型框架选择正确的加载接口。
d. 模型构建：通过rknn.build() 接口构建RKNN模型，可选择是否进行量化，提高模型在硬件上推理的性能。
e. 模型导出：通过rknn.export_rknn() 接口将RKNN模型导出成一个文件（.rknn 格式），用于后续部署。

2.模型评估：

该阶段的主要目标是评估模型推理结果的准确性、推理性能和内存占用等关键指标。评估的主要步骤如下：
a. 模型连板调试：使用Python连接RKNPU平台对模型进行推理并验证结果准确性。这个阶段涵盖了输入数据的前处理和输出结果的后处理，以确保模型在板上运行正确。
b. 精度评估：通过rknn.accuracy_analysis() 接口，比较量化模型与浮点模型推理结果之间的差异，以分析量化误差的来源。
c. 性能评估：通过rknn.eval_perf() 接口，分析模型在RKNPU平台上的推理性能，帮助用户进一步优化模型结构，加快推理性能。
d. 内存评估：通过rknn.eval_memory() 接口，了解模型在RKNPU平台上的内存使用情况，帮助用户进一步优化模型结构，最小化内存占用。

3.板端部署：

这个阶段涵盖了模型的实际部署和运行。它通常包括以下步骤：
a. 模型初始化：加载RKNN模型到RKNPU平台，准备进行前处理。
b. 模型前处理：加载待推理数据到RKNPU平台，准备进行推理。
c. 模型推理：执行推理操作，将输入数据传递给模型并获取推理结果。
d. 模型后处理：获取推理结果进行后处理，后处理结果传给应用端。
e. 模型释放：在完成推理流程后，释放模型资源，以便其他任务使用RKNN模型。

什么是智能体？

发表于 2026-06-19 更新于 2026-07-01 分类于 大模型和智能体

智能体（Agent）

定义：

在人工智能领域，智能体 (Agent) 是指一个能够自主感知环境、进行思考推理，并采取行动以实现特定目标的计算系统。

Agent = LLM (大脑) + Planning (规划) + Memory (记忆) + Tools (工具)

核心原理：

大模型本身只是一个“下一个词预测器”，它没有主动性。而 Agent 是给大模型套上了一个运行循环（Loop），使其具备以下四个要素：

  1. 感知（Perception）：接收用户的指令、网页输入或传感器数据。
  2. 大脑（LLM / Planning）：通过 Prompt 工程（如 ReAct 框架、CoT 思维链）让大模型分析现状，决定“下一步该做什么”，并把大任务拆解为小任务。
  3. 记忆（Memory）：
    • 短期记忆：当前的对话上下文、执行步骤。
    • 长期记忆：通过向量数据库（RAG）读取历史经验或外部知识。
    • 行动（Action）：调用外部工具去执行任务（比如查数据库、发邮件、跑代码）。

通俗解释：

普通大模型是“懂很多理论的军师”，你问它什么它都能答，但它自己没办法去办；而 Agent 是“有手有脚的特工 / 助理”，你给它一个目标，它会自己想办法去完成。

案例：

你对 Agent 说：“帮我订一张下周二去北京最便宜的机票。”

Agent 的思考过程：

  1. （规划）我需要先查今天几号，再查下周二的日期。
  2. （行动/工具）调用“日历工具”发现下周二是个公历日期。
  3. （行动/工具）调用“机票API”查询所有航班和价格。
  4. （思考）比对后发现 A 航班最便宜。
  5. （行动/工具）调用“支付/订票API”为你锁定机票，并发送确认短信（或生成付款链接）。

MCP (Model Context Protocol, 模型上下文协议)

定义：

MCP（模型上下文协议） 是一个开放的标准协议，它允许开发者构建安全的、双向的通道，使大模型（LLM）能够无缝连接到数据源（如数据库、文件系统）和开发工具（如 IDE）。

原理：

在 MCP 出现之前，如果想让大模型读你的 GitHub 仓库、查你的 Postgres 数据库，每个开发者都要自己写一套对接代码（即硬编码的 Tool Calling）。 MCP 效仿了互联网时代的 HTTP 协议 或开发领域的 LSP（语言服务器协议），提出了一个统一的架构：

  • MCP 客户端 (Client)：大模型应用（如 Claude Desktop、Cursor、智能体框架）。
  • MCP 服务端 (Server)：各种数据源或工具的适配器（如 GitHub MCP Server、Slack MCP Server、Postgres MCP Server）。 只要大家都遵守 MCP 协议，大模型就能像插上 USB 闪存盘一样，即插即用地访问任何支持该协议的外部数据和工具。

通俗解释：

MCP 就像是电子设备的 USB-C 统一接口。以前每款手机、电脑都有自己的充电口和数据线（各种定制 API 接口），乱成一团。有了 USB-C（MCP），不管你是接鼠标、U盘还是显示器，一根线插上就能用。

案例：

你使用一个支持 MCP 的 AI 编辑器（Client），它通过 MCP Postgres Server 直接读取了你本地数据库的表结构，又通过 MCP Git Server 读取了你的代码提交记录。你只需说一句：“帮我优化这个查询”，AI 就能同时看完数据库和代码，直接把改好的代码提交上去。

Skills (技能)

定义：

在大模型和智能体生态中，Skills（技能） 是指封装好的、高层级的、可复用的特定功能模块或任务执行能力。它通常由一段特定逻辑的代码、一组 Prompt 提示词以及定义好的输入输出接口（API）组合而成。

原理：

如果说大模型拥有“通用智商”，那么 Skills 就是它后天学习到的“专业技能证书”。 在大模型内部，Skills 的本质是 Tool Calling（工具调用）或 Function Calling（函数调用）的一种高级封装。

  1. 技能描述（Manifest）：用自然语言写明“这个技能是干什么的，需要什么参数”。大模型就是通过阅读这段描述，来判断什么时候该调用这个技能。
  2. 执行逻辑（Execution）：技能背后的实体，可以是一段 Python 代码、一个现成的 Web API（比如天气预报接口），甚至是一个子 Agent。

通俗解释：

大模型就像是一个“刚毕业的大学生”，智商很高，但什么具体的活都不会。你给它安装了一个“Excel 高级图表技能包”，它就立刻学会了怎么把数据变成折线图。

案例：

你在 Coze 平台上搭建一个“小红书爆款文案 Agent”，你可以给它配置三个 Skills：

  • 技能 A：【爆款爬取】自动抓取当前某个话题下点赞最高的 10 篇帖子。
  • 技能 B：【风格模仿】将任意文字一键转换成带有大量表情符号（Emoji）的小红书网感文案。
  • 技能 C：【配图生成】根据文案内容，自动调用 Midjourney 接口生成一张 3:4 的配图。 当用户输入一个主题时，Agent 就会依次调用这三个 Skill 来交付最终成果。

三者如何协作开展工作的？

用户向 Agent 下达任务。Agent 通过 MCP 协议安全地读取了你电脑里的工作文档（连接了上下文），接着它发现需要分析数据，于是调用了自己携带的“数据可视化 Skill”，最后把完美的图表生成并保存到了你的本地文件夹中。
